# ResearchOps workspace instructions

Before changing this project, read `PROJECT_TRACKER.md` and `README.md` completely.

Use `PROJECT_TRACKER.md` as the source of truth for completed work, the active milestone, acceptance criteria, dependencies, blockers, and the next implementation task. Do not rebuild or replace features marked DONE unless the user explicitly requests it or a verified defect requires it.

Before ending any development session, update the tracker with:

- feature status changes;
- the current and next task;
- verification results;
- new decisions or blockers;
- a dated session-log entry.

Never store credentials or secret values in the tracker or repository.
